- 状态：draft
- 日期：2026-10-28（Asia/Shanghai）

- 需求来源：基于项目现状和目标完善技术路线，形成有技术深度、可复用 LLM/Agent 技术的产品设计。
- 方案正文：[TECHNICAL_ROADMAP.md](../TECHNICAL_ROADMAP.md)

## 问题与证据

目前产品已具备导入、搜索、pack、MCP 和本地工作台，但查询主要按时间选取资料；引用绑定会变化的 item 而非不可变内容版本；没有模型运行层、任务恢复、可解释上下文编译或语义检索评测。只增加模型调用不能解决证据质量、历史一致性和任务可靠性。

本次完成设计与调研，给出阶段、边界和验证门槛；不安装新框架、不下载模型、不调用付费推理、不修改运行时行为。

## 目标与非目标

目标：将 Evidplane 演进为面向个人工程工作的证据与上下文平台。核心能力为版本化证据、段落级引用、任务上下文编译、可恢复的受限 Agent，以及可度量的检索/回答质量。

非目标：通用聊天产品、无限自治 Agent、微服务/Kubernetes、多租户、公网部署、平台代发，以及在没有评测增益时叠加向量库、图数据库或多 Agent 框架。

## 架构方案

保留 connectors / lake / serve 数据面与 Console。候选扩展为：

- Lake 内增加版本、片段、检索、确定性编译和物化结果模块；不引入模型网络调用。
- `intelligence/` 管理模型适配、结构化抽取/生成和策略；模型结果为候选派生物。
- `workflows/` 编排入库后处理与问答任务；主要候选 LangGraph，使用持久 checkpoint；它不替代 Lake 的证据与业务运行记录。
- Console service 调用工作流公共接口；MCP 原有只读工具保持兼容，新增能力逐项设计、协商并验证。

推荐评测 SQLite FTS5 + sqlite-vec + RRF，比较轻量多语 embedding 与 BGE-M3；重排按独立消融决定。Docling 用于需要版面定位的文档；Ragas 作辅助评测；OpenTelemetry 作观测接口，Langfuse 为可选后端。框架事实与边界见方案中的官方资料链接。

这些是候选架构，尚未修改 AGENTS 导入许可或 DECISIONS 中的既定决定。

## 契约与失败语义

- 区分 item、源版本、归一化文档版本、segment、claim、pack 和 run；引用必须能定位到不可变版本与原文范围。
- raw-only replay 需要带完整归一化快照的版本化 envelope；旧 payload 不足以恢复时明确报告缺口。
- 检索、重排、上下文缓存和恢复任务都应用相同的来源/时间/可见性约束。
- LLM 抽取不能直接写成已审核事实；引用有效性由代码校验，语义支持另行评测。
- 模型外发由用户配置与资料策略决定。未启用时，原有本地检索/pack 可继续使用。
- 工作流以至少一次执行和幂等提交设计；checkpoint 不等于外部副作用或计费 exactly-once。
- 原文更新、断源、撤销访问和删除是不同事件；依赖失效、缓存与正在运行任务的处理见路线正文。

## 数据与兼容

后续实施须采用显式 schema migration 和可验证 export manifest，保留已有 item_id、raw URI、MCP 工具与现有接口。新 citation/version 契约增量引入，不能把历史 item 引用伪装成版本引用。

`intelligence/` / `workflows/` 的依赖边界、runtime/checkpoint 备份、恢复和部署变化须在对应实施 spec 中确定。原备份只有 DB + raw，不能自动视作未来运行状态的完整备份。

## 设计验收标准

- AC-1：逐项核对当前代码、数据契约、现有评测和机器约束，区分已交付与建议目标。
- AC-2：给出产品核心场景、用户可感知能力、目标架构及自建/复用边界。
- AC-3：设计证据版本/引用、检索/重排、上下文编译、模型策略、任务恢复和知识审核的完整链路。
- AC-4：提供主方案、替代方案、触发引入条件及官方来源；不以宣传性能代替本项目验证。
- AC-5：给出按依赖排序的阶段、首个纵向交付、质量/成本/延迟指标与失败退出条件。
- AC-6：明确下一项实施的范围和验收；本次不改变产品运行行为。

## 验证计划

设计按代码入口、契约、阶段依赖与参考来源逐项审查；检查文档链接与 diff。纯设计不新增重复实现的测试。未来 embedding、LLM 或 Agent 性能门槛为待实测目标，不记作本次已达结果。

## 后续实施拆分

S0 评测与接口基线 → S1 证据版本/envelope/replay → S2 混合检索 → S3 可解释上下文编译 → S4 受限问答 Agent → S5 知识物化与审核。具体范围与退出条件见路线正文。

下一项建议为 S0 + S1，不在本 spec 中直接批准实现。其他阶段分别形成可审查的子 spec，避免一次批准无限扩展。
